## Overview

This project simulates an IoT monitoring and control system using the Wokwi online
simulation platform. The simulated ESP32 circuit communicates with a custom Node-RED
dashboard over MQTT (Message Queuing Telemetry Transport), enabling real-time
bi-directional data flow — sensor readings are pushed to the dashboard, while the
dashboard sends control signals back to the circuit.

## Tech Stack
- **Wokwi** — Browser-based circuit simulation
- **Node-RED** — Flow-based dashboard and MQTT orchestration

## Components
- ESP32
- DHT22 temperature & humidity sensor
- LED + 1kΩ resistor
- WS2812 NeoPixel ring
- Servo motor

## How It Works

### Circuit (Wokwi)

The circuit is built on Wokwi with the following connections:

![Circuit designed on Wokwi](/assets/img/posts/nodered/wokwickt1.png)

The relevant pin definitions from the sketch:

```cpp
#define DHTPIN    12    // DHT22 data pin
#define LED       26    // LED anode (via 330Ω resistor)
#define SERVO_PIN  2    // Servo signal pin
#define LED_PIN    4    // NeoPixel data pin
#define NUM_LEDS  16    // Number of LEDs in the ring
```

---

**DHT22 Temperature & Humidity Sensor** (4-pin):

| DHT22 Pin | ESP32 Pin |
|-----------|-----------|
| VCC       | 5V        |
| GND       | GND       |
| DATA      | GPIO 12   |
| NC        | —         |

The sensor is interfaced using the `DHT_U.h` library. Every second, the ESP32 reads
the temperature and humidity values and publishes them as a comma-separated string to
the `Tempdata` MQTT topic:

```cpp
// Inside loop() — non-blocking, fires every 1000ms
sensors_event_t event;

dht.temperature().getEvent(&event);
if (!isnan(event.temperature)) {
  temp = event.temperature;
}

dht.humidity().getEvent(&event);
if (!isnan(event.relative_humidity)) {
  hum = event.relative_humidity;
}

// Publish as "temp,hum" CSV string
msgStr = String(temp) + "," + String(hum);
client.publish(topic, msgStr.c_str());
```

---

**LED** (2-pin):

| LED Pin | ESP32 Pin              |
|---------|------------------------|
| Anode   | GPIO 26 (via 1kΩ)     |
| Cathode | GND                    |

The LED can be toggled on and off directly from the dashboard.

---

**Servo Motor** (3-pin):

| Servo Pin | ESP32 Pin |
|-----------|-----------|
| VCC       | 5V        |
| GND       | GND       |
| Signal    | GPIO 2    |

Controlled using the `ESP32Servo.h` library. A dashboard slider sends angle values
(0–180°) to the `servo` MQTT topic, which the ESP32 uses to position the motor.

---

**WS2812 NeoPixel Ring** (4-pin):

| NeoPixel Pin | ESP32 Pin |
|--------------|-----------|
| VCC          | 5V        |
| GND          | GND       |
| DIN          | GPIO 4    |
| DOUT         | —         |

DOUT is used for daisy-chaining multiple rings together; since only one ring is used
here, it is left unconnected. The ring is interfaced using the `FastLED.h` library,
with color controlled via a dashboard color picker.

---

All three peripherals are controlled through the MQTT `callback()` function, which
fires whenever a message arrives on a subscribed topic:

```cpp
void callback(char* topic, byte* payload, unsigned int length) {
  String data = "";
  for (int i = 0; i < length; i++) {
    data += (char)payload[i];
  }

  // LED on/off
  if (String(topic) == "lights") {
    digitalWrite(LED, data == "ON" ? HIGH : LOW);
  }

  // Servo angle
  else if (String(topic) == "servo") {
    int degree = data.toInt();
    servoMotor.write(degree);
  }

  // NeoPixel RGB color
  else if (String(topic) == "lights/neopixel") {
    int r, g, b;
    sscanf(data.c_str(), "%d,%d,%d", &r, &g, &b);
    fill_solid(leds, NUM_LEDS, CRGB(r, g, b));
    FastLED.show();
  }
}
```

---

### MQTT Topic Map

| Topic            | Direction         | Payload format   | Controls          |
|------------------|-------------------|------------------|-------------------|
| `Tempdata`       | ESP32 → Dashboard | `temp,hum`       | Sensor readings   |
| `lights`         | Dashboard → ESP32 | `ON` / `OFF`     | LED               |
| `servo`          | Dashboard → ESP32 | `0`–`180`        | Servo angle       |
| `lights/neopixel`| Dashboard → ESP32 | `r,g,b`          | NeoPixel color    |

---

### Dashboard (Node-RED)

Node-RED is used to build the MQTT flows and dashboard UI that communicate with the
Wokwi circuit.

![Flow created on Node-RED](/assets/img/posts/nodered/noderedflow1.png)

The flow is structured as follows:

- An **MQTT In** node subscribes to `Tempdata` and feeds data to two function nodes —
  *Extract Temperature* and *Extract Humidity* — which split the incoming `temp,hum`
  CSV string. The extracted values drive a **gauge** and a **chart**, updating live on
  the dashboard.

- A **button node** (*LED*) on the dashboard toggles the LED, publishing `ON` or `OFF`
  via an **MQTT Out** node to the `lights` topic.

- A **slider node** (*Servo*) sends values from 0 to 180 to the `servo` topic via an
  **MQTT Out** node, controlling the servo angle.

- A **color picker node** (*NeoPixel Color Picker*) feeds into a *Parse RGB Values*
  function node, which converts the default color object into a plain `r,g,b` string
  that the ESP32 can directly parse with `sscanf`. This is then published to the
  `lights/neopixel` topic.
